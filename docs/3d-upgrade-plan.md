# 3D 与场 · 升级方案（提案）

> 状态：**方案待选**，本文只做对标与设计，不改代码。
> 日期：2026-10-24
> 现有实现：`src/ui/SpacePanel.svelte` / `src/ui/SpaceView.svelte` / `src/render3d/*` / `docs/3d.md`

## 一、结论

不建议整体替换现有 three.js 渲染层，也不建议把 GeoGebra 或 VTK.js 直接搬进来。更稳的路线是：

- **交互骨架对标 GeoGebra 3D**：对象列表 → 选中对象 → 属性检查器 → 画布；
- **视觉与呈现对标 MathBox**：坐标系统、标签、色带、流线/曲面质感、镜头过渡；
- **场分析能力对标 ParaView Glance / VTK.js**：切片、等值面、传递函数、探针、流线与体积渲染清单；
- **底层继续使用当前 three.js + 纯 TypeScript 数学模块**，按需吸收上述项目的交互和算法，不引入大依赖。

推荐落地顺序：**先做「3D 工作台」→ 再做「场分析」→ 最后做「演示/体积渲染」**。

## 二、现有能力审计

当前 3D 与场已经不是一个“空白模块”，基础很扎实：

- 四类对象：曲面（显式/隐式/参数/旋转体/多面体）、空间曲线、向量场、ODE；
- Marching Tetrahedra 隐式曲面、解析/数值法线、LOD 参数、空曲面警告；
- 切平面 + 符号偏导、等高线投影、二重积分、散度/旋度着色；
- 相机保存、上下文丢失恢复、30fps 限帧、PNG/GIF 导出；
- 参数化预设与参数滑块；文档/撤销/分享体系完整。

### 主要缺口

1. **对象管理仍偏“表单”**：左侧面板同时放添加、对象、视图、分析、积分、导出，长且没有真正的对象检查器。
2. **缺少对象级显示控制**：可见性、颜色、透明度、标签、线宽、渲染质量分散在不同位置。
3. **缺场分析闭环**：没有切片/裁剪平面、标量场探针、色标、传递函数、等值面滑杆；向量场只有箭头密度/比例和流线种子数量。
4. **缺镜头工作流**：没有 top/front/side/iso 预设、镜头书签、过渡动画，也没有把相机状态纳入分享。
5. **性能旋钮不够显式**：分辨率、质量、帧率没有形成“草稿/标准/精细”三档预设。
6. **视觉表达仍偏基础**：坐标轴/网格/标签、曲面网格线、光照、色标与遮挡关系可再提升。

## 三、开源项目对标

| 项目 | 类型 / 许可 | 最值得借鉴 | 不照搬 |

## 四、三套可选包

### 方案 A · 轻量 3D 工作台（推荐先做）

目标：**先把“添加/选择/调整/查看”做顺**，不引入新数学能力。

- 左侧：对象库（预设卡片 + 自定义方程 + 对象列表）；
- 右侧检查器：选中对象的类型、表达式、定义域、颜色、透明度、分辨率、显示/隐藏；
- 画布顶部浮动视图条：透视/正交、top/front/side/iso、重置、坐标轴/网格/标签；
- 色标（colorbar）+ 悬停探针；画布内显示选中点坐标；
- 质量三档（草稿 / 标准 / 精细）+ 实时 FPS；
- 把二重积分、导出从长表单移到检查器的「分析 / 导出」分组；
- 保留现有全部对象类型、撤销、保存、分享、PNG/GIF。

适合：先把当前 3D 页面从“设置表单”变成真正的 3D 工作台。

### 方案 B · 场分析工作台（推荐完整目标）

在 A 的基础上增加：

- **标量场**：色域自动/手动、传递函数编辑、等值面滑杆、切片平面、裁剪平面；
- **向量场**：箭头/锥体/线段三种 glyph、密度/比例/归一化、按模长/散度/旋度着色、流线种子/步长/长度；
- **探针**：点击画布读取 `(x,y,z)`、场值、梯度、散度、旋度；
- **分享**：URL 恢复相机、可见性、着色、切片/裁剪、色域；
- **预设**：标量场、向量场、切片、流线各 3–5 个教学预设。

适合：让「3D 与场」从“能画曲面”升级为“能分析场”；与现有数学教育定位高度一致。

### 方案 C · 完整科学可视化

在 B 的基础上增加：

- GPU 体积渲染（3D texture + ray marching）与传输函数编辑器；
- 高级裁剪/剖切、光照/阴影/环境光遮蔽、标注与测量；
- 镜头书签、路径动画、课堂演示脚本；
- 可选 VR/AR 与独立场景导出。

适合：明确要做“科学数据可视化”而不只是数学教学；成本和性能风险最高。

## 五、推荐路线与验收

### 阶段 1 · v3.12「3D 对象检查器」

- 新增 `SpaceInspector.svelte`：对象属性、显示、分析、导出四组；
- 新增 `SpacePresetGallery.svelte`：曲面/曲线/场/ODE 分组卡片；
- 新增 `SpaceViewBar.svelte`：投影、视角预设、重置、轴/网格开关；
- 新增 `Colorbar.svelte` + `SpaceProbe.svelte`；
- 调整 `SpacePanel.svelte`：只保留“添加/对象列表/预设”；
- `state/space-state.svelte.ts` 增加 `selectedSpaceId`、`quality`、`viewPreset`、`colorRange`；
- 验收：加对象 → 选中 → 改颜色/透明度/分辨率 → 视角预设 → 色标/探针 → 分享恢复；单测/ e2e 全绿。

### 阶段 2 · v3.13「场分析」

- 标量场采样与等值面：复用 Marching Cubes，新增 `isoValue` 与滑杆；
- 切片/裁剪：three.js clippingPlane + 截面绘制；
- 向量场 glyph：InstancedMesh，按模长/散度/旋度着色；
- 流线：种子点、步长、最大长度、RK4，与现有 `streamline2D` 统一；
- 探针与场读数；
- 验收：一套标量场 + 一套向量场预设，支持切片、等值面、流线、探针与分享。

### 阶段 3 · v3.14「呈现与体积」

- 镜头书签、过渡动画、注释、参数动画；
- 体积渲染（可选，按数据需求决定是否做）；
- 课堂演示模式联动；
- 验收：镜头书签可分享；演示模式下大字/低干扰；体积渲染有明确性能档位。

## 六、架构与文件

```text
src/ui/
  SpacePanel.svelte           # 添加 / 对象列表 / 预设入口（变短）
  SpaceInspector.svelte       # 选中对象属性（新）
  SpacePresetGallery.svelte   # 预设卡片（新）
  SpaceViewBar.svelte         # 画布顶部视图条（新）
  Colorbar.svelte             # 色标（新）
  SpaceProbe.svelte           # 探针读数（新）
src/state/
  space-state.svelte.ts       # 选中、质量、视角、色域、切片状态
src/render3d/
  scene.ts                    # clipping / slice / instanced glyphs / camera presets
  fields.ts                   # 场采样、流线、div/curl
  surfaces.ts                 # 等值面/分辨率/质量档
src/state/types.ts            # SpaceObject 显示与分析字段
```

原则：

- **数学与渲染继续分离**：纯 TS 采样/等值线/MC 不进 three.js；
- **现有对象类型不重写**：只加可选的显示/分析字段，提供默认值与迁移；
- **不直接依赖 MathBox/VTK.js**：借鉴交互和算法；如未来做体积渲染，再评估按需引入 three.js 体积示例或 VTK.js 子模块。

## 七、风险

| 风险 | 说明 | 控制 |
|---|---|---|
| 场分析范围膨胀 | 体积渲染/传递函数很容易变成另一个产品 | 先做 B，C 作为可选包 |
| 低端设备性能 | 箭头/流线/切片叠加后三角形与 draw call 增加 | InstancedMesh、质量档、限帧、LOD |
| 对象字段兼容 | 旧文档没有新字段 | 全部字段可选 + 默认值，序列化测试 |
| 3D UI 拥挤 | 左表单刚拆完，又容易堆满 | 继续用右检查器 + 手风琴分组 |
| 过度引入依赖 | MathBox/VTK.js 与现有场景重复 | 只做参考，不整体替换 |

## 八、建议选择

- 想快速改善观感与操作：选 **A**；
- 想真正升级「3D 与场」：选 **B（推荐）**；
- 明确要做科学数据/体积分析：选 **C**，并先单独做性能原型。

我的建议是 **A → B 的核心场分析**，暂不做体积渲染；这样能在一个可控范围内把 3D 工作台、对象检查器、色标/探针、切片和流线补齐。
