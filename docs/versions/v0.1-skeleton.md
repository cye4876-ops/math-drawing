## 工作内容

| # | 任务 | 说明 |
|---|---|---|
| 1 | 初始化仓库 | `git init`、`.gitignore`、首次提交 |
| 2 | Vite + TypeScript 工程 | 严格模式（`strict: true`、`noUncheckedIndexedAccess`） |
| 3 | 测试框架 | Vitest（单元）+ Playwright（端到端），各跑通一个样例测试 |
| 4 | 代码规范 | ESLint + Prettier，配 pre-commit 钩子 |
| 5 | **许可证扫描** | 加入脚本与 CI，扫描依赖树 |
| 6 | CI 流水线 | GitHub Actions：安装 → 类型检查 → lint → 测试 |
| 7 | **坐标系与视图变换** | 数学坐标 ↔ 屏幕坐标双向转换、缩放、平移的纯函数模块 |
| 8 | **分层渲染骨架** | Canvas 层 + DOM 覆盖层的容器，处理 devicePixelRatio 与 resize |
| 9 | **store + 撤销/重做** | 单一状态源，基于命令模式或不可变快照的 undo/redo 栈 |
| 10 | 最小可运行界面 | 一个空白坐标系 + 网格 + 网格刻度数字，能缩放平移 |

**任务 7/8/9 是本版真正的技术内容**，其余是脚手架。它们会被后续每一版复用，所以值得认真写。

## 验收标准

### 功能验收

- [ ] `pnpm dev` 一条命令启动，浏览器打开即见空白坐标系与网格
- [ ] 滚轮缩放、拖拽平移可用，**缩放与平移不会被撤销栈记录**（视图操作不入历史）
- [ ] 窗口 resize 后画布不模糊（devicePixelRatio 处理正确）
- [ ] 网格刻度数字随着缩放自动变化，不出现重叠或跳变
- [ ] 撤销/重做：至少能对一次"添加对象"操作生效，`Ctrl+Z` / `Ctrl+Shift+Z` 可用

### 质量验收

- [ ] `pnpm typecheck` 零错误（strict 模式）
- [ ] `pnpm lint` 零警告
- [ ] `pnpm test` 通过，且**坐标变换模块的单元测试覆盖往返一致性**（正向变换后反向变换应回到原点，误差 < 1e-9）
- [ ] Playwright 至少一个端到端用例：打开页面 → 断言画布存在
- [ ] CI 在 push 后自动运行且通过
- [ ] 许可证扫描无 GPL/AGPL 依赖

### 文档验收

- [ ] README 进度表将 v0.1 标记为已完成
- [ ] CONTRIBUTING.md 写明开发命令与提交规范

## 风险与陷阱

| 陷阱 | 说明 |
|---|---|
| **把渲染架构想简单** | 分层渲染的边界如果一开始划错，v0.5 必然返工。**开工前先读 [TECH-STACK.md](../TECH-STACK.md) 第二节** |
| **撤销粒度没想清** | 视图缩放该不该入历史？参数拖动过程中要不要合并成一步？现在不定义，后面每加一个功能都要重新讨论 |
| **过早引入状态库** | 先手写，确认需求后再决定是否引入第三方 store |
| **strict 模式留到最后开** | 必须开局就开，否则后面改不动 |

## 验收方式

```bash
pnpm install
pnpm typecheck
pnpm lint
pnpm test
pnpm dev          # 手工验证：缩放、平移、resize、撤销
pnpm exec playwright test
```

**人工确认项**：在浏览器里缩放 10 次、平移 10 次，确认网格刻度始终可读、画布始终清晰。
