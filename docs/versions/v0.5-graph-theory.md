## 为什么是架构分水岭

到这一版，画布上同时存在**连续曲线**与**离散节点/边**，两者在四个方面完全不同：

| 维度 | 曲线 | 图元素 |
|---|---|---|
| 缩放语义 | 随视图缩放（数学意义） | **节点尺寸应基本恒定**（屏幕意义） |
| 命中检测 | 沿路径的最近点 | 节点圆形/边的线段距离 |
| 撤销粒度 | 多曲线增删 | 单节点/单边的增删拖动 |
| 数据模型 | 表达式 + 参数 | 顶点集 + 边集 + 属性 |

**对策**：把渲染层重构成**图形元素注册制**——每个元素自报"如何绘制"与"如何命中"，而不是继续堆 `if` 分支。

```
GraphicElement = {
  id, type,
  draw(ctx, viewport),
  hitTest(screenPoint): HitResult | null,
  getBounds(): Rect,
  serialize(): JSON
}
```

**收益**：v0.8 的 3D 对象、v1.0 的 Notebook 单元格元素都能复用这套注册机制，无需再动渲染核心。

## 工作内容

### 1. 数据模型

- **顶点**：id、标签、位置（数学坐标）、颜色、大小、形状、自定义属性
- **边**：起点、终点、**有向/无向**、权重、样式、**支持自环与重边**
- 整个图可序列化为 JSON（沿用 v0.3 的文档模型）

**底层用 `graphology`** 承载数据结构与算法——它只做数据与算法，**不带渲染器**，与自研渲染层不冲突。

### 2. 输入方式（双向同步）

| 方式 | 说明 |
|---|---|
| **画布直接操作** | 点击空白建点、拖拽连边、拖动节点、右键菜单删除 |
| **文本 DSL** | 如 `A-B:3, B-C:2, C->A`，实时解析并同步到画布 |
| **矩阵导入** | 粘贴邻接矩阵（CSV/TSV），自动建图 |
| **预置图族** | 完全图 $K_n$、二分图 $K_{m,n}$、环 $C_n$、路 $P_n$、树、Petersen 图、超立方体 $Q_n$、网格图 |

**文本 DSL 与画布必须双向同步**——这是本版的重要体验点，也是最容易做歪的地方。

### 3. 布局算法

| 布局 | 用途 | 实现 |
|---|---|---|
| **力导向（ForceAtlas2）** | 通用 | 用 `graphology-layout-forceatlas2`，**启用 WebWorker 模式**避免阻塞主线程 |
| **分层布局** | DAG、依赖图 | 参考 Graphviz 的 Sugiyama 算法（分层 → 交叉最小化 → 坐标分配） |
| **环形布局** | 环状结构 | 简单，自行实现 |
| **网格布局** | 规则结构 | 简单 |
| **手动** | 用户拖动 | 拖拽后固定，可选"回弹" |

**手感要求**：拖动节点时有物理惯性感，松手后自然回弹而非瞬移。

### 4. 算法可视化（逐步动画）

每个算法都要：**逐步执行、可暂停、可单步、可回退、可调速度**。

| 算法 | 可视化重点 |
|---|---|
| **BFS / DFS** | 队列/栈状态、访问顺序着色 |
| **Dijkstra** | 距离表更新、已确定集合边界 |
| **Bellman-Ford** | 松弛过程、负环检测 |
| **Floyd-Warshall** | 距离矩阵逐格更新（矩阵视图同步高亮） |
| **Prim / Kruskal** | 最小生成树的边逐步加入 |
| **拓扑排序** | 入度归零的节点依次出队 |
| **强连通分量** | Tarjan 或 Kosaraju 的栈状态 |
| **二分图匹配** | 匈牙利算法的增广路寻找 |
| **最大流** | 残量网络与增广路径 |

**实现要求**：算法必须实现为**可中断的生成器**（`function*`）或状态机，而非一次性算完——否则无法单步与回退。

### 5. 属性面板

- 邻接矩阵、关联矩阵、**拉普拉斯矩阵**（可视化热力图）
- 度数序列、度分布
- 连通性、二分性判定
- 欧拉路径 / 哈密顿路径存在性判定
- 直径、平均路径长度、聚类系数

### 6. 图着色

- 贪心着色（按度数降序）
- 显示色数上界
- 四色定理演示（平面图）

### 7. 矩阵视图 ↔ 图视图联动

点击矩阵中的格子，高亮对应边；高亮边时矩阵对应格也亮起。**这个联动是理解图论概念最有效的交互之一。**

## 风险与陷阱

| 陷阱 | 说明 |
|---|---|
| **在旧渲染逻辑上打补丁** | 本版最大的风险。**必须重构为元素注册制**，否则 v0.8、v1.0 会持续受苦 |
| **力导向参数调不好** | 会像果冻一样抖。需要反复试参（引力、斥力、弹簧长度、阻尼）。**预留调优时间** |
| **算法一次性算完** | 无法单步/回退。**必须用生成器或状态机实现** |
| **布局在布局过程中阻塞主线程** | 必须用 WebWorker（graphology 的 FA2 自带） |
| **DSL 与画布同步产生循环更新** | A 改 B、B 又改 A 导致无限循环。需**单向数据流 + 变更来源标记** |
| **节点尺寸随缩放变化** | 缩小时节点变成看不见的小点。节点尺寸应在**屏幕空间**恒定 |
| **曲线与图元素的 z-order 混乱** | 需明确的图层顺序与用户可调的置顶/置底 |
| **图算法边界情况** | 空图、单点图、不连通图、有向无环图——**测试必须覆盖** |

## 验收方式

```bash
pnpm test src/graph            # 图算法正确性
pnpm test                      # 全量回归（含 v0.3/v0.4）
pnpm bench                     # 布局性能
pnpm dev
```

**人工确认项（逐个走一遍）**：

1. 生成 Petersen 图 → 运行 3 着色 → 确认用 3 色
2. 手建带权图 → 运行 Dijkstra → 逐步播放 → 核对路径
3. 粘贴一个邻接矩阵 → 确认图正确生成
4. 切换到文本 DSL → 改一个权重 → 确认画布同步
5. 拖动节点感受手感（是否果冻、是否卡顿）
6. 回到函数绘图标签页 → **确认 v0.3/v0.4 功能未因重构而退化**
