| 项目 | 内容 |
|---|---|
| **主题** | 交互 Notebook、教学辅助、插件接口、打包分发 |
| **前置依赖** | **全部前序版本** |
| **相对投入** | ████ 4（含打包分发，常被低估） |
| **产出** | 收官版本——**但这是节点，不是终点** |

> ⚠️ **v1.0 不是终点而是节点。** 数论可视化、更多算法、LaTeX 排版这些可以无限延伸。所以本版的重点放在**插件接口**上：先把扩展点定好，之后加模块是"写一个插件"而不是"改一遍核心"。

## 工作内容

### 1. Notebook 单元格系统

**单元格类型**：

| 类型 | 内容 |
|---|---|
| **文本格** | Markdown + KaTeX 公式 |
| **图形格** | 任意前序模块的视图（函数图、图论、统计、3D、复变...） |
| **计算格** | 表达式求值、符号计算、数值结果 |
| **数据格** | 表格数据，可作为其他格的输入 |

**核心能力**：

- **跨格变量引用**：前序格子定义的参数/变量可被后续格子引用（形成依赖图）
- 依赖变更时**级联更新**后续格子
- 单元格可拖拽排序、折叠、复制、删除
- 每格独立执行，也可"全部运行"

**这是把前面所有模块组装成"文档"的一层。**

### 2. 导出 Notebook

- **HTML**（自包含，含交互）—— 可在浏览器打开，图形可交互
- **PDF**（静态，适合打印与提交）
- Markdown + 图片（适合 GitHub）
- LaTeX（复用 v0.6 的 TikZ 导出，拼装成完整文档）

### 3. 教学辅助

| 功能 | 说明 |
|---|---|
| **题目模式** | 系统出题（画指定函数、求根、作图论算法），学生操作 |
| **自动判定** | 比对学生的图与标准答案（容差可配） |
| **参数动画录制** | 拖动参数自动生成动画并导出（复用 v0.6） |
| **演示模式** | 全屏、隐藏编辑 UI、大字体，适合课堂投影 |
| **预设示例库** | 常用教学场景的一键示例（导数几何意义、黎曼和、Dijkstra...） |

### 4. 插件接口（**本版真正的战略重点**）

把扩展点定好，让后续加模块不需要改核心：

| 扩展点 | 允许插件做什么 |
|---|---|
| **表达式函数** | 注册自定义数学函数 |
| **图形元素** | 注册新的可绘制元素类型（复用 v0.5 的元素注册制） |
| **工具** | 注册新的交互工具（复用 v0.4 的工具抽象） |
| **视图类型** | 注册新的视图/面板类型 |
| **导出格式** | 注册新的导出器 |
| **单元格类型** | 注册新的 Notebook 单元格类型 |

**插件形式**：至少支持**本地 JS 模块加载**；是否做正式的插件市场留作后续决策。

**必须有**：完整的插件开发文档 + 一个示例插件（如"注册一个新的数学函数 + 一个新的图形元素"）。

### 5. 打包与分发

| 项目 | 内容 |
|---|---|
| 静态站点 | 构建产物可部署到任意静态托管 |
| **PWA** | 可安装、离线可用（Service Worker） |
| **桌面版（可选）** | 用 **Tauri** 打包（比 Electron 小约 10 倍） |
| 版本与更新 | 语义化版本；更新日志 |
| 许可证 | 明确项目自身的开源许可证 |

### 6. 性能打磨

- 全模块性能回归测试
- 首屏加载优化（代码分割、懒加载重型模块如 three.js）
- 大文档场景下的响应性

## 风险与陷阱

| 陷阱 | 说明 |
|---|---|
| **依赖图出现循环** | A 引用 B、B 引用 A → 死循环。**必须有拓扑排序 + 环检测** |
| **级联更新过频** | 每个字符输入都触发全量重算会卡死。需**防抖 + 增量更新** |
| **HTML 导出变成截图** | 失去交互性就失去了意义。**导出后图形必须仍可交互** |
| **插件接口设计过窄** | 接口定窄了，后续加模块还是要改核心。**至少要覆盖 6 类扩展点** |
| **插件无隔离** | 一个插件报错拖垮整个应用。需要错误边界 |
| **打包体积失控** | three.js 等重型模块必须代码分割 + 懒加载 |
| **PWA 缓存策略写错** | 会导致用户永远拿到旧版本。**必须有更新机制** |
| **为了 v1.0 而赶工** | 收官版本容易为了"完成度"牺牲质量。**宁可延后，不要凑数** |
| **忘记写"不支持什么"** | `limitations.md` 比功能列表更能建立信任 |
