界面优化对标
与三套可选方向

先看成熟数学工具和图分析工作台的设计取舍，再选择适合 Math Drawing 的整体壳。当前需求不是“换配色”，而是让 9 个工作区、画布和计算面板形成稳定的信息层级。

我的初步判断 推荐以“三栏分析工作台”为主，吸收 Desmos 的画布优先、Gephi Lite 的手风琴分组和 Quiver 的上下文工具条；教学演示模式保留“舞台式”布局。

01 · 当前界面：优点与主要问题

现有界面已经有清晰的浅色视觉体系、浮层和深色画布；问题主要是“功能都露在外面”，画布被多个浮层同时切割，高级功能在垂直方向上无限堆叠。

函数绘图：画布优先，但浮层过多

视觉克制表达式快捷输入左栏留白过大
  • 三个浮层同时压在画布上：左侧曲线卡、底部工具 dock、底部开始绘图卡。
  • 左侧“曲线”输入区与底部“标记点”之间出现大片空白，信息密度失衡。
  • 底部 13 个工具全部常驻，图标为主、文字很小，初学者难以扫读；画布有效面积被压缩。
  • 右上角全局图标没有文字标签，功能发现性弱。

极值计算台：功能完整，但像“控件清单”

深色画布 / 结果可视化单列超长滚动结果与操作分离
  • 精确搜索、附加禁图、结构约束、总表、分享、启发式、Turán、Ramsey、超图 Turán 全部纵向堆叠。
  • 一次只做一件事的用户要滚很远；无法判断“下一步该做什么”。
  • 结果在画布底部/状态栏，操作在左栏，视线来回跳。
  • 深色画布与白色面板对比强，适合专注，但面板缺少层级和锚点。

02 · 参考项目：值得借鉴什么

下面 4 个参考覆盖两类产品：数学绘图工具（Desmos、GeoGebra）和图/关系分析工作台（Gephi Lite、Quiver）。截图仅用于内部设计对标，来源见页面底部。

Desmos · 极简双栏（非开源，UX 标杆）

画布优先表达式即对象颜色联动

优点

  • 只保留输入列表和画布，其他功能在需要时出现。
  • 表达式、颜色、曲线一一对应，编辑反馈非常直接。
  • 左侧可收起，画布始终是主角。

不要照搬

  • 高级分析几乎全部隐藏，不适合极值/超图工作台。
  • 对 9 个工作区的导航没有参考价值。

GeoGebra · 图标导航 + 可切换视图

工具分组视图切换触屏输入

优点

  • 左侧窄图标栏统管“代数区 / 工具 / 表格 / 数据”，内容面板随视图切换。
  • 图形区占据绝对主位，底部键盘可收起。
  • “分发/分享”是明确的主操作。

不要照搬

  • 图标密度高、部分图标语义弱，学习成本高。
  • 视觉风格偏老，面板层级依赖大量小图标。

Gephi Lite · 图分析工作台（开源）

手风琴工作流Graph / Data 顶层切换画布内图例

优点

  • Layout / Appearance / Filters / Metrics 一次只展开一个，渐进披露做得很好。
  • 左侧固定工作流，右侧浮动工具条，画布保持最大面积。
  • 图例与统计浮在画布内，结果离图很近。

不要照搬

  • 一次只开一个面板，频繁切换时效率一般。
  • 部分控件偏小，中文长标签需要重新设计。

quiver · 全屏画布 + 上下文工具条（开源）

全屏画布悬浮紧凑工具条快捷键优先

优点

  • 画布几乎占满全屏，工具条悬浮且分组清晰。
  • 顶部“保存/撤销/选择/变换”和底部“导入/导出”分离，符合任务阶段。
  • 选中对象后出现上下文操作，界面不预先堆满。

不要照搬

  • 对新手过于“空白”，没有引导和状态解释。
  • 深色单主题、强快捷键依赖，不适合宽用户群。

03 · 三套可选方向

不是三套配色，而是三种信息架构。选择一套作为主壳，其他两套可以作为“课堂演示模式”或局部交互吸收。

改动小收益中

A · 极简双栏

Desmos / quiver 路线：画布最大，编辑面板可收起，工具只在选中时出现。

主画布
适合函数绘图、图论绘图、课堂演示
优点认知负担最低，画布最完整，视觉最现代
代价高级功能难发现；极值/超图工作流需要深度改造
推荐改动大收益高

B · 三栏分析工作台

GeoGebra + Gephi Lite 路线：左侧工作流、中央画布、右侧检查器、底部结果抽屉。

主画布
适合整套工具，尤其是极值、超图、统计和 3D
优点功能有层级、结果离画布近、可扩展到 9 个工作区
代价需要重排现有面板；窄屏要改成抽屉；实现量最大
课堂优先收益高

C · 教学舞台

画布全屏，底部 3–4 步引导条，结果以大卡片浮层出现，面板按需召唤。

全屏画布
适合课堂演示、新手引导、单次探究任务
优点步骤清晰、干扰最少、投影效果最好
代价高级用户重复操作变慢；不适合作为唯一主界面

建议：B 作为主壳，A 和 C 作为两种模式

Math Drawing 不是单一函数绘图器，而是 9 个工作区。全局壳必须能承载“输入 → 操作 → 画布 → 结果”的完整链路。B 的三栏结构最稳；A 用于函数/图论绘图的专注模式，C 用于课堂演示模式。

全局导航改为“工作区切换 + 当前工作区工具轨”，不再平铺 9 个标签。
所有右侧面板按“输入 / 约束 / 输出”手风琴分组，一次只展开一组。
结果进入右侧检查器或底部抽屉，并在画布内给轻量高亮/图例。
先做极值台和函数绘图的壳，验证后再推广到其余工作区。

04 · 已落地：B 三栏工作台

全局壳已按 B 方案落地，并用同一套结构覆盖全部 9 个工作区。左侧工作区轨负责切换，编辑栏固定在工作流侧，画布保持独立，右侧检查器集中工具、视图与项目操作；原先覆盖画布的底部工具坞已移除。窄屏改为横向工作区轨 + 上半屏画布 + 下方编辑栏/检查器滚动。

函数绘图

  • 左侧曲线输入、中央画布、右侧分析与视图控制三段分离。
  • 首屏引导保留在画布底部，不再与工具坞叠加。
  • 工具栏只保留项目级操作，模式切换移入左侧工作区轨。

图论绘图

  • 图族、DSL、性质、谱与算法仍在左侧工作流，滚动范围独立。
  • 图编辑工具与读数进入右侧检查器，不再占用画布底部。
  • 画布始终完整可见，适合点选与拖拽。

超图、彩虹与极值

  • 左侧长工作流拥有独立滚动区，不遮住深色画布。
  • 右侧检查器显示当前工作区提示、视图与项目操作。
  • 极值搜索、总表、证书等原有功能与 testid 保持不变。

极值结果右栏

  • 搜索结果生成后，证书卡片、极大性、极图画廊与饱和图出现在右侧检查器。
  • 左侧只保留搜索控件和结果摘要，生成结果后不再继续向下拉长。
  • 极值模式下右栏自动加宽到 360px，便于阅读 graph6 与不变量。

窄屏适配

  • 工作区轨变为横向可滚动条，画布固定在上半屏。
  • 编辑栏与检查器在画布下方依次排列，整体可滚动。
  • 状态栏回到文档流底部，不再浮动遮挡操作。

验收结果

三栏壳、左右栏独立开关、极值结果右栏与窄屏适配已完成；保留全部既有功能与 testid，并新增三栏顺序、检查器收起与九工作区切换的 e2e 覆盖。
