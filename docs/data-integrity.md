# 数据完整性审计（v3.12.1）

按“从文档、导入导出、持久化到渲染数据”的顺序做了一次全链路检查。目标不是增加功能，而是保证：

- **可往返**：保存/分享/重新打开后，文档中的字段不丢失；
- **可拒绝**：损坏、越界或互相矛盾的数据不会进入文档或渲染层；
- **可降级**：单个损坏记录不会让整个页面或 Notebook/实验台崩溃。

## 修复清单

| 区域 | 问题 | 修复 |
|---|---|---|
| 3D 文档 | 隐式曲面的 `isoValue` 未写入/读回，重新打开后 `F = c` 回到 0 | `parseSurface3D` 保留有限 `isoValue` |
| 3D 文档 | 向量场 `colorMode: 'magnitude'` 读回时被降为 `none` | 合法颜色模式加入 `magnitude` |
| 文档导入 | 两个对象可使用同一个 id，选择/渲染/撤销会串线 | `deserializeDocument` 拒绝重复对象 id |
| 视图 | 分享/导入中的 `scaleX/scaleY = 0`、负数或 NaN 会让投影与命中测试失效 | `parseView` 与 `sanitizeView` 统一夹取缩放、清理非有限值 |
| 图对象 | 重复顶点/边 id、悬空边端点和非有限坐标可进入文档；graphology 转换会抛错或画错 | `normalizeGraphDoc` 校验 id 唯一、端点存在、坐标有限；尺寸/权重回退安全默认值 |
| 数据集 | 图表列索引可指向不存在的列（尤其首列为文本时） | 导入时把 `xColumn/yColumn/column` 夹取到实际列范围；单列缺省图表改为直方图 |
| CSV 导入 | 首列为文本时，默认散点图仍选第 0/1 列，导致空白图 | `tableToDataset` 从数值列中选择默认 x/y；单数值列选实际数值列做直方图 |
| 大 CSV | 分片解析把每片首行文本数据误当表头而丢失，且 `textColumns` 未合并 | 后续分片补合成表头；合并 `textColumns` 并统一置空文本列 |
| Notebook | 重复单元格 id、损坏的 figure 快照/视图可导致执行或渲染异常 | 拒绝重复 id；figure 快照与视图走文档校验，失败给出单元格位置 |
| 超图 | 完整 JSON 格式允许重复超边 id | 解析时拒绝重复超边 id |
| 实验档案 | 残缺记录只按 id 过滤，渲染或复算时可能崩溃 | 按实验/构造/比较的必需字段逐条校验，损坏记录丢弃 |
| 3D 场 | 幅值溢出为 Infinity 或散度/旋度非有限时，NaN 可能进入几何缓冲 | 采样与渲染层跳过非有限幅值/标量 |

## 仍保留的边界

- CSV 分片解析仍不支持**跨分片边界的引号内换行**（同步解析支持）；这是大文件流式解析的已知限制。
- 实验档案只做结构与类型校验；数学规格在“复算”时仍由 `validateGraphSpec` / `validateHyperSpec` 再做语义校验。
- 插件对象的 `data` 由插件自行解释，核心层只保留其 JSON 可序列化形态。
